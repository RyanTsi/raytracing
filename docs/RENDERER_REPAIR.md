# 修复与验证记录

日期：2026-10-22。本文件记录第一轮渲染核心修复及当时的测试数据；后续贴图、相机和 PMX 能力见 [第二轮验收](TEXTURES_AND_CAMERA.md)，最终 Git 状态见 [历史整理](HISTORY.md)。第一轮完成时尚未提交，后续已统一整理。

## 原实现的主要问题

| 问题 | 影响 | 本次处理 |
|---|---|---|
| SSBO 临时对象以默认复制赋给 map，随后析构删除同一 GL buffer | 上传时使用失效的缓冲区，是阻断性错误 | SSBO 独占所有权、禁止复制、显式移动；真实 GL 生命周期测试 |
| 从默认屏幕缓冲区 glCopyTexImage2D 回写，内部格式改为 GL_RGB | HDR 与精度丢失，逐帧重分配/复制 | 两张 RGBA32F FBO 交替读写，独立显示 pass |
| 每帧模糊上一帧后再积分；双边滤波还把分辨率当成纹素尺寸 | 不是原样本平均，细节持续扩散 | 历史只做线性运行平均，不对累积数据做模糊 |
| 半球采样分布不正确，却统一乘 2π；人为混合反射方向没有匹配 PDF | 光照有偏，噪声和金属高光异常 | 余弦漫反射与 GGX NDF 的混合采样，用完整混合 PDF 更新吞吐量 |
| 直接光代码被注释，完全依赖随机路径撞灯 | 许多路径没有贡献 | 矩形面积光采样、阴影 any-hit、与 BSDF 的 MIS |
| 直接看灯被排除，出射辐射亮度额外乘余弦 | 光源可见性及亮度错误 | 所有深度求交灯面，仅正面发光，不在发光值中额外乘余弦 |
| 像素随机数依赖帧耗时与 sin 哈希 | 采样相关，难复现 | 整数哈希与 PCG 风格状态，像素/样本/用户种子独立确定 |
| 平移全屏 quad 做抖动 | 边缘可能漏绘，射线采样并未正确实现亚像素抖动 | quad 固定覆盖，抖动在每个像素的相机射线内完成 |
| 相机 45 度直接传入 tan | 投影视角错误 | GLSL 显式 radians，并使用正交相机基 |
| 三角形用严格内部不等式排除边缘，UV 重建索引也错误 | 接缝漏交、无效属性 | Möller–Trumbore 包含边界；直接读取打包三角形，删除错误 UV 重建 |
| 同距离命中取决于遍历顺序 | BVH 与直接求交在共享边上可产生差异 | 精确等距时按原始三角形 ID 打破平局，回归图逐值一致 |
| AABB 的零方向倒数可能产生 0 × infinity；不按最近命中距离裁剪 | 平行边界不稳定，多做无效遍历 | 显式平行 slab 分支、最近距离裁剪、近子树优先 |
| BVH 内部保存 vector 元素裸指针，空输入 reserve 下溢 | 复制后悬空、空场景异常 | 孩子及图元使用索引，空 BVH 合法；导入无三角形场景报错 |
| 每层整段排序、轴循环中分 | 构建及遍历效率受限 | 12 桶 SAH，退化时 nth_element 中分，限制 SAH 深度以保护 GPU 栈 |
| 逐个 mesh 按值复制再生成 GPU 数据 | 无谓复制顶点/索引 | 遍历改用 const 引用 |
| 没有应用导入节点变换，直接访问可能缺失的法线 | glTF/其他层级场景错位或崩溃 | Assimp PreTransformVertices 与 GenSmoothNormals，专门图像回归 |
| 材质未指定 metallic 就默认 1；光源颜色 normalize | 普通物体变金属，颜色幅度改变 | metallic 默认 0，粗糙度限制在稳定范围，保留光源颜色 |
| 着色器与模型是旧机器绝对路径，GL 版本未请求，CMake 使用未定义 target | 难以构建、运行失败不清晰 | 源码根目录资源定位/--root、请求 4.3 Core、编译链接失败直接报错、Release 预设 |

新积分器使用迭代吞吐量，不再存储整条路径栈；第四次表面反弹后使用俄罗斯轮盘。硬深度范围为 1–16，达到上限的路径仍存在截断误差。GGX 最小粗糙度为 0.045，未实现真正的 delta 镜面。平滑法线只做朝向与几何半球约束，未实现完整的 shading-normal 能量修正。

MIS 使用同一立体角测度下的 PDF：面积光 PDF 包含距离平方、灯面余弦、灯面积和选灯概率；BSDF PDF 是两种采样分布的混合。灯面命中的发光项与 NEE 用 power heuristic 加权，关闭 MIS 时关闭重复的 BSDF 灯面贡献。实现思路参考 [PBRT 第四版：A Better Path Tracer](https://pbr-book.org/4ed/Light_Transport_I_Surface_Reflection/A_Better_Path_Tracer)。浮点累积与显示分离使用标准 OpenGL 浮点纹理和 FBO，格式依据 [Khronos glTexImage2D 文档](https://wikis.khronos.org/opengl/GLAPI/glTexImage2D)。

## 实际验证

环境：Windows，MSVC 19.44，Release，NVIDIA GeForce RTX 5070，OpenGL 4.3 / NVIDIA 617.42。本次未验证其他显卡、驱动和平台。

`cmake --preset windows-release`、`cmake --build --preset windows-release`、`ctest --preset windows-release` 均通过。CPU 测试包括空/单图元/4096 随机/4096 重心重合 BVH、完整覆盖、包围关系、复制移动、GPU 打包字段和相机基。GPU 冒烟测试检查真实着色器编译链接、四种 SSBO 的驱动实际 stride、移动所有权、历史重置、渲染目标重建、有限非负 HDR 读回和 GL debug 错误。

`tests/validate_render.py` 的完整对照通过，原始命令与数据保存在 `captures/validation/results.json`：

| 检查 | 结果 |
|---|---|
| 默认场景：强制 BVH vs 直接求交，128×80、32 spp | 所有 HDR 像素逐值相同，最大绝对差 0 |
| 背包：67,907 三角形，96×64、8 spp、3 次反弹 | 两种求交的 HDR MSE = 0 |
| glTF 节点旋转/平移/非均匀缩放 vs 烘焙 OBJ | HDR MSE 约 1.50e-17 |
| 缺失法线的 OBJ | 加载及出图成功 |
| 两个独立进程、相同种子和参数 | HDR 逐值相同，仅限本次 GPU/驱动环境 |
| 在非项目工作目录执行 | 资源查找与 GPU 冒烟测试通过 |
| 无效参数、丢失模型 | 非零退出码，明确错误 |
| 每次图像验证 | 有限、非负 HDR，GL error 0 |

图像误差以独立种子 73、4096 spp 的同一积分器作为参考，使用线性 HDR RGB MSE。它用于发现不收敛和比较采样效率，**不是独立物理真值**。分辨率 128×80，六次反弹：

| 方案 | spp | 线性 RGB MSE | 单帧 GPU 光追中位数 |
|---|---:|---:|---:|
| 均匀半球、关闭 NEE | 16 | 0.345740 | 0.0576 ms |
| 均匀半球、关闭 NEE | 32 | 0.158760 | 0.0580 ms |
| 新 BSDF 采样 + NEE + MIS | 16 | 0.003691 | 0.0961 ms |
| 新 BSDF 采样 + NEE + MIS | 256 | 0.0002345 | 0.0936 ms |

同为 16 spp 时误差约低 93.7 倍；用各自中位数估算累计 GPU 预算，MIS 16 spp 约 1.54 ms，均匀 32 spp 约 1.86 ms，后者误差仍高约 43 倍。这是固定场景和种子的实测，不能推广为任意场景都快同样倍数；均匀半球基线是修复后积分器的消融模式，也不是原始错误 shader。

4096 spp 的三种估计方式（MIS、仅 NEE、仅 BSDF）平均线性 RGB 分别约 0.195263、0.195304、0.195342，最大相对差约 0.0404%，未出现明显双重计算能量的迹象。16→256 spp 的 MSE 下降约 15.7 倍，与渐进收敛一致。

性能是 **GL_TIME_ELAPSED 测得的光追 pass GPU 时间**，不等于包含 UI、显示、VSync、加载和保存的 FPS：

| 对照 | GPU 单帧中位数 |
|---|---:|
| 30 三角形：强制 BVH，128×80 | 0.1560 ms |
| 30 三角形：直接求交，128×80 | 0.0947 ms |
| 67,907 三角形：BVH，96×64 | 0.7722 ms |
| 67,907 三角形：暴力求交，96×64 | 111.0780 ms |
| 默认场景：960×600，64 spp | 1.9140 ms |
| 默认场景：480×300，64 spp | 0.5210 ms |

因此默认对 <=64 三角形使用直接求交，大场景走 BVH。背包的约 144 倍优势是**相对禁用 BVH**，不能称为比原项目快 144 倍：原项目本来就有 BVH，且存在阻断性错误，未得到可直接比较的原始运行基线。半分辨率预览相对全分辨率的光追耗时约低 3.67 倍。

最终示例 `captures/final.png`：960×600、4096 spp、六次反弹、种子 1，GPU 光追中位数约 1.93 ms，渲染循环加 GPU 排空约 9.34 秒，不含初始化和保存图像。完整参数（包括相机）在同名 JSON 中。

## 交互验收与使用

通过原生窗口交互检查过实际 GLFW/ImGui 窗口：暂停后 spp 保持；调曝光使显示变亮而保持 2038 spp；Restart 回到 1 spp；最大化后重建为新分辨率并从 1 spp 开始；按 Esc 退出。右键观察与 WASD 是代码实现的控制路径，本次未用自动化模拟持续按住鼠标右键拖动。相机移动、渲染目标尺寸与样本重置另有 GPU 自动测试。

UI 显示采样数、分辨率、图元数、遍历方式、GPU 时间与窗口 FPS，支持暂停、相机复位、曝光、反弹数、环境亮度、渲染比例、目标 spp、诊断开关和导出。控制相机时重置历史并降低采样分辨率，静止后恢复高分辨率累积。渲染与窗口 framebuffer 尺寸相匹配，最小窗口尺寸限制避免参数区过窄。

## 第一轮结束时的能力边界（后续已有扩展）

第一轮结束时仍是教学/实验渲染器。贴图和法线贴图、透明/玻璃折射、模型自发光、导入灯光、HDRI、体积、运动模糊、自动曝光和降噪未实现；材质 opacity 虽读入，但积分器按不透明表面处理。默认添加的是程序矩形光源，不能称为完整还原原模型灯光。较高分辨率下移动预览仍要重新采样，未做时域重投影。

OpenGL shader 在 GPU 上自行遍历 BVH，**没有使用 RTX RT Core / DXR / Vulkan Ray Tracing**。大量三角形、很多灯光或复杂玻璃焦散仍需要更深入的结构调整。当时建议的后续工作是补贴图/法线和基础玻璃，再加入保存法线/深度辅助通道的独立显示降噪；若要充分利用 RTX 硬件求交，再单独迁移 DXR/Vulkan 后端。降噪应保持原始 HDR 累积不变。
